# 运行时帧时间监测：0.1.1-playtest.4

本轮针对“平均 FPS 较高，但飞行仍有细微不稳定感”增加实际游玩采集。沿用 .3 的飞行手感和显示插值，保存、物理和手柄配置不变。监测默认关闭，通过客户端命令开启；不自动降低渲染距离或调整垂直同步。

## 游玩采集

在原 FPV 版本启动游戏、进入世界后执行：

```text
/fpvperf start 120
```

屏幕右侧显示最近帧时间曲线、平均间隔、P95/P99、峰值、渲染提交、交换缓冲、限帧等待和服务端保存情况。先悬停，再在同一区域绕圈高速飞行；出现不舒服的瞬间，可用 `/fpvperf mark 卡顿` 添加时间标记。120 秒后自动停止，也可以提前执行 `/fpvperf stop`。

需要进一步区分 GPU 绘制时间时使用 `/fpvperf startgpu 120`。它读取异步时间查询；查询还未完成或池已满时跳过样本，不等待 GPU 完成。`/fpvperf hud off` 可隐藏面板继续采集，减少面板绘制对结果的影响；`hud on` 恢复显示。

`/fpvperf target 120` 设置报告参考预算：120 FPS 对应 8.33 ms，60 FPS 对应 16.67 ms；默认 120。该命令不改变游戏帧率或垂直同步，需要在采集前执行。持续时间允许 5–600 秒。`/fpvperf status` 查看状态和上次报告位置。

## 导出和解释

结果在当前游戏目录的 `performance-diagnostics/perf-.../`，本机原 FPV 对应 `F:/Desktop/.minecraft/versions/FPV/performance-diagnostics/`。停止后后台生成：

- `report.html`：离线交互曲线，可开关指标、缩放、查看保存区间和标记。
- `frames.csv`：保留的逐帧原始数据。
- `events.csv`：服务端 tick、保存、无人机 tick、目标更新接收和 GC 观测。
- `summary.json`：P50/P95/P99、峰值、抖动、超预算次数、保存时间线及样本保留情况。
- `README.md`：各项定义和缺失值解释。

优先看 `interval_ms` 的尖峰与 P99，而不只看平均 FPS。帧间隔是连续帧开始之间的实际时间，包含等待；`total_wall_ms` 是整次帧调用墙钟时间。渲染、交换缓冲和限帧分别计时，可以分辨慢帧主要出现在哪个范围，但部分范围有嵌套，不能简单相加。

`work_wall_ms` 只从总墙钟时间扣除交换缓冲和明确限帧等待，仍可能包含驱动或其他等待，不能当作纯 CPU 执行时间。GPU 查询只覆盖 `GameRenderer.render` 的 GPU 时间跨度，可能包含提交期间的空闲，不包含清屏、最终 blit、交换缓冲、限帧或显示扫描，也不等于 GPU 利用率。空白或 JSON null 表示缺失，不能当作零。

保存与帧尖峰出现在同一时间，只能说明相关。若帧间隔稳定而服务端/无人机 tick 出现长间隔，画面可以继续刷新，但实际飞行状态更新会停顿。姿态和位置目标接收间隔不是网络延迟或丢包率；静止或数值未变化时可能没有同步更新。GC 是每秒最多一次的累计收集耗时增量观测，不能精确定位单次暂停。

`all` 包含所有保留帧；`gameplay` 仅包含有世界、窗口有焦点、无界面且未暂停的帧。命令输入、暂停和切出窗口的影响可以通过这两组与原始标志位区分。隐藏窗口的功能测试没有用户显示器上的呈现节奏，不能当作实际流畅度基准。

## 实现边界

帧和事件各保留最多 65,536 行，采集只向有界原始数值数组追加，不逐帧写盘。停止后封存，快照及报告生成均在单独后台线程；上一份尚在导出时拒绝开始新采集，避免无界排队。覆盖行、未完成帧/保存和 GPU 缺失计数写入报告。HTML 最多展示 3,000 个按帧间隔峰值选出的点，其他曲线的独立峰值可能省略，精确分析使用 CSV。

GPU 使用 8 组时间戳查询，仅在两端查询均可用时读取结果。它与原版调试面板的 elapsed 查询类型分开；停止、异常和关闭时清理，不调用 `glFinish`。嵌套的 `runTick(false)` 不作为普通渲染帧重复计数；停止后迟到的 GPU/服务端事件按捕获编号拒绝。

运行环境元信息使用允许列表：版本、Java/OpenGL、分辨率、垂直同步和距离/限帧选项；不额外采集账号、用户存档路径、姿态坐标或原始手柄设备标识。报告无需外部网络资源。退出时最多等待报告写入 5 秒；若磁盘写入未完成，残留 `.partial` 目录不属于完整报告。

## 安装和验证

本轮直接更新用户指定的原 FPV `mods`。专用安装器核对 .3/.4 哈希，拒绝运行中或重复 Mod 的实例，把旧版移到版本目录的 `fpvdrone-mod-backups/` 后安装 .4；API、选项、手柄配置和存档不变。它与先前创建独立 PCL 实例的安装器分别使用。

验证记录随发布包的 `verification/` 交付。单元测试检查环形覆盖、帧/等待范围、迟到 GPU、封存后写入、保存重叠和实体切换。客户端 GameTest 检查真实消息处理入口、命令和导出，明确标记为合成测试；普通生产运行使用独立超平坦世界，检查 CPU/GPU 采集、原版 GPU 面板共存、自动停止、重启采集、完整退出和保存重开。功能测试结果不能证明当前用户世界的剩余卡顿原因，下一步依据本次实际游玩的报告判断。

实际验证通过：各模块 JUnit 结果共 1,382 项，无失败、错误或跳过；其中 Fabric 611 项、监测存储回归 9 项。服务端 9/9 GameTest 通过，客户端已注册命令、真实消息入口、途中停止和后台导出检查通过。最终 .4 生产 JAR 使用原 FPV 的 68 项运行库、Fabric API 0.141.6 和 LWJGL 3.3.3-snapshot 完成普通世界中的 CPU/GPU 采集、自动导出、原版 GPU 调试共存、重启/退出和重进验证，进程退出码 0。独立安装器在 Windows PowerShell 5.1 下通过成功安装、重复运行，以及已有文件被改动、重复 Mod、新文件哈希错误时的拒绝检查。离线报告和 GPU 面板截图已检查。
